### Notes per construct

**GETTIMEDATE.** Both give a 7-element FIX UVECTOR
`![sec min hour day month year usec!]`. `<GETTIMEDATE 0 T>` gives
0 0 0 1 1 1970 0, and `![0 123456!]` gives 123456 µs. Both reject a STRING
argument and a third argument.

**MAPR.** All 11 agree: REST views are passed (TYPE LIST for each
position), iteration stops at the shortest input, PUT through the view
mutates the source, and `<MAPR <> ...>` returns the last value (`(2)`,
`[4]`). *Coverage gap (still open):* `tests/mapr_test.rkt` has no MAPSTOP,
MAPLEAVE or MAPRET case under MAPR. Those are covered only for MAPF
(`tests/mapf_test.rkt`). The behaviour agrees today, but no regression
test pins it.

**SPNAME.** `<SPNAME NORTH>` is a shared STRING (`==?` across calls is T).
Writing to it fails with "String is immutable" in Confusion and
"immutable STRING literal cannot be mutated" here. `PNAME` is a fresh,
mutable copy (`"XORTH"`). `<SPNAME 1>`: Confusion calls MDL ERROR
(`*ERROR* "FIRST-ARG-WRONG-TYPE" SPNAME 1`, LISTENING-AT-LEVEL 2; the
stderr line "Atom REP has neither LVAL nor GVAL" is the normal side message
when an error level is entered, not a crash). Ours raises a host error
("expected an MDL ATOM, got 1"). The same non-modelling of MDL ERROR is
already documented for MAX and ABS (SEMANTICS "M4: ABS", Refusals). The
2026-11-22 note described this as a "REP crash", which was wrong.

**MOBLIST.** TYPE OBLIST, identity across calls, and the size argument
agree. Without a prior `<MOBLIST R9T>` in the same process,
`<GET R9T OBLIST>` is `#FALSE ()` in both. After it, `<GET name OBLIST>` is
the OBLIST and `<GET oblist OBLIST>` is the name (`==?` T in both). The
three "bidirectional" differences are printing only: Confusion prints
`#OBLIST ![() ... ()!]`, while our UNPARSE refuses OBLIST (the TYPE is
OBLIST and the `==?` results agree). `GETPROP` is an explicit unimplemented
error here (SEMANTICS "M2 D5", the GETPROP/PUTPROP bullet: "the pinned load
set never uses them"). In Confusion it acts like GET (`#FALSE ()`, or the
OBLIST). No MDL source file in the pinned checkout contains GETPROP. It
appears only in the binary save files `MDL/MADADV.SAVE` and
`SAVEFILE/ZORK.SAVE`.

**INCHAN/OUTCHAN, PRINTSTRING.** Both CHANNELs agree: LENGTH 19, mode
`"PRINT"`/`"READ"`, slot 10 `""`. TERPRI writes LF and returns `#FALSE ()`.
CRLF writes LF and returns `T`. PRINTSTRING writes the same characters
(`hello`, or `hel` with count 3). Confusion **returns the STRING** (`"hello"`
even with count 3, TYPE STRING). Ours **returns the count** (5 or 3,
TYPE FIX). `<==? <PRINTSTRING "hello"> "hello">` is `#FALSE ()` in both,
because the two literals are different objects. Manual §11.4.2.2
([chapter 11](https://mdl-language.readthedocs.io/en/latest/11-input-output/)):
PRINTSTRING "outputs buffer on channel, either the whole thing or the first
count characters, and returns the number of characters output". So this
is a manual-vs-Confusion question, and the runtime follows the manual.
The 2026-11-22 note said the manual returns the string, which is
incorrect. Both reject an input CHANNEL and a negative count.

**MIN/MAX.** Both agree on the two-argument results and FLOAT contagion
(`<MIN 4 2.0>` 2.0, `<MAX 4 2.0>` 4.0), `<MIN <MIN> 1>` = `<MAX <MAX> 1>`
= 1.0, TYPE FLOAT for both zero-argument values, `<G? <MIN> 1.0>`,
`<L? <MAX> 1.0>`, `==?`/`=?` of `<MIN>` with itself, and rejecting an ATOM
argument. They differ as follows:

- `<MIN>` printed by the REPL: Confusion dies with SIGSEGV (exit -11, no
  stdout). `<TYPE <MIN>>`, `<CHTYPE <MIN> FIX>` and arithmetic on it work,
  so only printing the value itself crashes (the mechanism was not
  investigated). Ours returns FLOAT (2^27−1)·2^100 = 1.7014118219281863e+38.
- `<CHTYPE <MIN> FIX>`: Confusion gives 9218868437227405311 =
  0x7FEFFFFFFFFFFFFF, the bit pattern of host `DBL_MAX` (the 2026-11-22
  note called it "NaN bits", which is incorrect). Ours gives
  34359738367 = 377777777777₈, the PDP-10 word that `77dung.mud:57` (BIGFIX)
  relies on.
- `<MAX>`: Confusion prints `0.0000000`. Its CHTYPE FIX image is
  4503599627370496 = 0x0010000000000000, host `DBL_MIN`, the smallest
  *positive* double, so it is not an identity for MAX. Ours gives FLOAT
  −(2^27−1)·2^100, with CHTYPE FIX −34359738367.

Manual §3.5 ([chapter 3](https://mdl-language.readthedocs.io/en/latest/03-built-in-functions/))
says the zero-argument identities are "the greatest FLOAT, and the least
FLOAT". MAX was missing at the 2026-11-22 capture. It now exists on main.

**ISTRING/IVECTOR/IUVECTOR.** ISTRING and IVECTOR agree. Each evaluates a
quoted fill once per element (`"ABC"` with C 64→67, `[1 2 3]` with N 0→3),
and a constant fill is copied (`[42 42 42]`). IUVECTOR
`<SETG N 0> <IUVECTOR 3 '<SETG N <+ ,N 1>>> ,N`: Confusion gives
`![2 3 4!]` and N=4, so it evaluates the fill one extra time. Ours gives
`![1 2 3!]` and N=3. Manual §7.5.4
([chapter 7](https://mdl-language.readthedocs.io/en/latest/07-structured-objects/))
says the expression "is re-EVALuated each time a new element is
generated", and its example `<SET A 0>` `<IUVECTOR 9 '<SET A <+ .A 1>>>`
gives `![1 2 3 4 5 6 7 8 9!]`. All four negative-length and non-CHARACTER
fill cases are errors in both.

**STRING REST views.** Both agree on `"bc"`, TYPE STRING, LENGTH 2, `==?`
of two equal views (T), aliasing (`"XYX"` and `"YX"` after a PUT through
the view), `<STRING <REST "hello" 2>>`, `<1 <REST "abc" 1>>` (`!\b`), and
PRINC of a view (writes `llo`, returns `"llo"`). Printing only:
`<ATOM <REST "ab" 1>>` prints as `b!-#FALSE ()` in Confusion, an ATOM on no
OBLIST. Ours makes an ATOM `b` that the current OBLIST path cannot reach,
and its UNPARSE refuses trailer notation (SEMANTICS "M3 BLOCK/ENDBLOCK":
print-time trailer selection is not implemented). `rest-string-spname`
fails in both, at the `.T` probe error.

## Other differences found (not in the e262860 list)

- GETPROP is unimplemented here (strict error); Confusion supports it.
  Documented gap (SEMANTICS "M2 D5"); no MDL source uses it. Not a defect
  under the strict-failure policy.
- OBLIST and trailer-ATOM printing: our UNPARSE refuses both (strict). The
  values agree where the cases test them. Already documented as
  unimplemented.
- Error delivery: Confusion either aborts to level 1 with a stderr message
  or enters an MDL ERROR level (`<SPNAME 1>`, the `.T` case). Ours raises a
  host error in both situations. Every deliberate-error case errors in
  both; only the text and the mechanism differ. Same pattern as documented
  for MAX/ABS.

No new behavioural mismatch affecting a game expression was found.

## Appendix: our-runtime harness (`$TMPDIR/r9/ours/run_ours.rkt`)

Read-only. It is derived from the #199 harness and adds an explicit
string output port, per-form terminal output, TYPE, FLOAT display, and
VECTOR/UVECTOR display through the runtime's own `mdl-length`/`mdl-nth`.

```racket
#lang racket/base
(require racket/list racket/string racket/port json racket/flonum
         mdl/parser mdl/compiler mdl/runtime/core mdl/loader)
(define args (current-command-line-arguments))
(define root (vector-ref args 0))
(define loader-ns (module->namespace 'mdl/loader))
(define core-ns (module->namespace 'mdl/runtime/core))
(define call-in-session (eval 'call-in-session loader-ns))
(define unparse-value (eval 'mdl-unparse-value core-ns))
(define type-name (eval 'mdl-type-name core-ns))
(define (tname v)
  (with-handlers ([exn:fail? (lambda (e) "?")]) (format "~a" (type-name v))))
(define mdl-length* (eval 'mdl-length core-ns))
(define mdl-nth* (eval 'mdl-nth core-ns))
(define atom-pname (eval 'atom-value-pname core-ns))
(define (show v)
  (define t (tname v))
  (cond [(flonum? v) (format "FLOAT ~a" v)]
        [(member t '("VECTOR" "UVECTOR"))
         (define items (for/list ([i (in-range 1 (add1 (mdl-length* v)))])
                         (show (mdl-nth* v i))))
         (if (equal? t "VECTOR")
             (string-append "[" (string-join items " ") "]")
             (string-append "![" (string-join items " ") "!]"))]
        [else (with-handlers ([exn:fail? (lambda (e)
                                           (if (equal? t "ATOM")
                                               (format "#<ATOM ~a: ~a>" (atom-pname v) (exn-message e))
                                               (format "#<~a>" t)))])
                (unparse-value 'r9 v))]))
(define (run-file cases-path out-path)
(define cases (hash-ref (call-with-input-file cases-path read-json) 'cases))
(define rows
  (for/list ([c (in-list cases)])
    (define expr (hash-ref c 'expression))
    (define out (open-output-string))
    (define session (make-mdl-session (string->path root)
                                      #:output-port out
                                      #:input-port (open-input-string "")))
    (define nodes (parse-mdl expr))
    (define forms
      (for/list ([node (in-list nodes)])
        (define r
          (call-in-session session
            (lambda ()
              (with-handlers ([exn:fail? (lambda (e) (hasheq 'error (exn-message e)))])
                (define v (eval (compile-expression node)))
                (hasheq 'value (show v) 'type (tname v))))))
        (flush-output out)
        (define written (bytes->string/utf-8 (get-output-bytes out #t) #\?))
        (if (string=? written "") r (hash-set r 'output written))))
    (hasheq 'name (hash-ref c 'name) 'expression expr 'forms forms)))
(call-with-output-file out-path #:exists 'truncate/replace
  (lambda (o) (write-json (hasheq 'cases rows) o)))
(printf "~a: ~a cases\n" cases-path (length rows)))
(let loop ([i 1])
  (when (< i (vector-length args))
    (run-file (vector-ref args i) (vector-ref args (add1 i)))
    (loop (+ i 2))))
```
