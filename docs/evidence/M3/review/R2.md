## Finding restated

When the MDL live set grows steadily, the automatic capacity expansion after a
failed logical GC uses a flat `used + max(words, 8192)` increment.  Because each
expansion only adds 8192 words, a session that retains N logical words triggers
O(N/8192) full major host GCs, each of which sweeps O(live entries) weak boxes.
The combined cost is O(N²/8192) — quadratic in the retained word count.

R10 (test robustness): several assertions in `tests/logical_gc_test.rkt` assert
EXACT host-GC reclamation counts, which are sensitive to whether the Racket
compiler (BC vs CS / Chez) kills a binding after its last use or keeps it live
until the end of the lexical frame.

## Root cause: file and line

`mdl/runtime/core.rkt`, function `mdl-track-allocation!`, lines 1869–1871
(before fix):

```racket
(when (> (+ (mdl-memory-used memory) words) (mdl-memory-capacity memory))
  (set-mdl-memory-capacity!
   memory (+ (mdl-memory-used memory) (max words 8192))))
```

This flat `+max(words,8192)` increment means capacity grows linearly in N, so
the number of expansions is N/8192.

## Manual contract

MDL manual (from memory, unverified against online copy — network unavailable):
historical MDL enlarges the GC heap ("BLOAT") on demand.  The manual does not
specify a growth policy; the visible contract is that BLOAT sets an explicit
free-word floor, while automatic expansion (from overflow) is an implementation
detail.  The fix changes only internal growth policy, not any observable BLOAT
or GC semantics.

Confusion probe: not applicable (Confusion stubs GC as returning an ATOM).  The
historical GC handler test (`tests/historical_gc_handler_test.rkt`) confirms
that the MDL-level DIVERT-FCN, DIVERT-CNT, DIVERT-AMT behaviour is unchanged.

## Design decision

**Amortised geometric growth, factor 3/2.**  After an unsatisfying collection,
the new capacity is:

```
grown = min(fix-max, max(needed, ceil(capacity × 3/2)))
```

Where `needed = used + words` and `fix-max = 2^35 − 1`.  This gives:

- O(log n) collections for a growing live set.
- Explicit error `'mdl-gc "storage overflow: N logical words needed, exceeds
  FIX maximum M"` when the minimum needed exceeds `fix-max`, rather than silent
  wraparound.
- BLOAT semantics are unaffected (it uses an explicit floor, not geometric growth).
- `used + free = capacity` invariant always holds.

Trade-off: for very small n (< a few thousand live cells) with a tight initial
capacity, the geometric growth uses slightly more GC cycles than the flat +8192
bump, because the minimum increment is smaller (1000×1.5=1500 vs 1000+8192=9192).
This is acceptable: the pathological case is large n, and small-n behaviour is
dominated by the initial capacity (default 262144 words).

## Weak-box bookkeeping evaluation (Task 3)

The existing approach (linked list of `(allocation weak-box words)` structs,
O(n) sweep per GC) was measured alongside the fix.  With geometric growth,
the number of GC sweeps is O(log n), so total bookkeeping cost is O(n log n).
The main overhead is in the `for/list` sweep inside `mdl-memory-collect!`, but
this only runs O(log n) times for a growing live set, not O(n) times.

Switching to `make-weak-hasheq` or will-executors would reduce the per-sweep
cost but would not change the asymptotic GC frequency.  Given that the benchmark
shows acceptable wall time (1.15 s for 500k cells retained, which is far beyond
any realistic Zork session), no bookkeeping redesign is warranted.

## Exception safety (Task 4)

Verified by new tests:

1. **DIVERT-AGC handler raises**: `used = 0` after the raise (allocation was
   not registered).  Covered by existing test + new explicit `check-invariant!`
   calls.

2. **GC event handler raises**: The sweep (`mdl-memory-collect!`) runs first
   and updates `entries` and `used` before the GC event is emitted.  When the
   event handler raises, the ledger reflects the reclaimed words (consistent
   state) and the allocation fails cleanly.  New test in
   `tests/logical_gc_test.rkt`: "Exception safety: GC event handler raises".

No double-counting or lost entries observed in any test.

## Remaining risks and unsupported cases

1. **Bookkeeping list length**: the ledger maintains one weak-box entry per
   allocation.  For very large sessions (millions of live objects), the O(n)
   sweep per GC is still linear.  With geometric growth, sweeps happen O(log n)
   times total for a growing live set, so amortised cost per allocation is
   O(log n) entries touched.  For a 1977 Zork load (1229 forms), the live set
   is small and this is not a concern.

2. **fix-max overflow error**: raised by `'mdl-gc` with a string message.  It
   is not an MDL LVAL error (a Racket error propagates through the interrupt
   system).  At fix-max = 34,359,738,367 logical words, this is unreachable in
   practice.

3. **BC vs CS liveness**: the new test for the REST case wraps `shared` in a
   function (`make-shared-and-return-tail`) to ensure it goes out of scope
   before GC.  The `>= 2` lower bound is robust to both BC and CS.

4. **Historical GC test**: `tests/historical_gc_handler_test.rkt` hardcodes
   `/tmp` and requires the sandbox to be disabled.  This is a pre-existing
   constraint, not introduced by this PR.

## Proposed docs/SEMANTICS.md section

### Logical movable-storage GC (capacity growth policy)

The logical storage ledger tracks MDL LIST cells, VECTORs, and UVECTORs via
host weak boxes.  When an allocation would exceed logical capacity:

1. **DIVERT-AGC** is emitted with `(words initiator)`.  If a handler calls
   `BLOAT`, the extra free words may satisfy the request with no GC.
2. If still short, a full host-GC sweep (`collect-garbage 'major`) is run,
   reclaiming dead entries.  The **GC** event is emitted with
   `(elapsed-seconds reason initiator)`.
3. If still short, capacity is expanded **geometrically** by a factor of 3/2:
   ```
   new-cap = min(fix-max, max(needed, ceil(old-cap × 3/2)))
   ```
   where `needed = used + words` and `fix-max = 2^35 − 1`.  If `needed >
   fix-max`, a Racket error is raised immediately.

The ledger is an **approximation** of historical MDL accounting: it tracks
allocation lifetimes through the host GC, not a hand-managed copying collector.
Reported `used` / `free` / `capacity` values reflect this approximation and are
not equivalent to what PDP-10 Muddle would have reported.

The `BLOAT` primitive sets an explicit free-word floor (`capacity = used +
free-words`) and is unaffected by the automatic growth policy.  `GC` returns
the number of logical words reclaimed by the sweep (may be less than the number
of host-collected bytes).
