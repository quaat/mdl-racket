## Finding restated

When the MDL live set grows steadily, the automatic capacity expansion after a
failed logical GC uses a flat `used + max(words, 8192)` increment.  Because each
expansion only adds 8192 words, a session that retains N logical words triggers
O(N/8192) full major host GCs, each of which sweeps O(live entries) weak boxes.
The combined cost is O(N²/8192) — quadratic in the retained word count.

R10 (test robustness): several assertions in `tests/logical_gc_test.rkt` assert
EXACT host-GC reclamation counts, which are sensitive to whether the Racket
compiler (BC vs CS / Chez) kills a binding after its last use or keeps it live
until the end of the lexical frame.

## Manual text — MDL Programming Language, ch.22 §22.5 and §21.10.3

Source: `MDL_Primer_and_Manual.pdf`, PDP-10 muddle repository,
`doc/MDL_Primer_and_Manual.pdf` (sha: github.com/PDP-10/muddle master, 2016
Adobe Acrobat Paper Capture scan, 270 pages). Text extracted with pdftotext.

**§22.5 GC** (verbatim, OCR artefacts in original preserved):

> `<GC min:fix exh?:false-or-any>`
>
> causes the garbage collector to run and returns the total number of words of
> storage reclaimed. Both of its arguments are optional; if they are not
> supplied, a call to GC simply causes a normal garbage collection.
>
> If min is explicitly supplied as an argument, a garbage-collection parameter
> is changed permanently before the garbage collector runs. min is the smallest
> number of words of "free" (unclaimed, available for use) movable
> garbage-collected storage the garbage collector will be satisfied with having
> after it is done. Initially it is 8192 words. If the total amount of reclaimed
> storage is less than min. it will ask the operating system for enough storage
> (in 1024-word blocks) to make it up. N.B.: the system may be incivil enough
> not to grant the request; in that case, the garbage collector will be content
> with what it has, unless that is not enough to satisfy a pending request for
> storage. Then it will inform you that it is losing. A large min will result in
> fewer total garbage collections, but they will take longer since the total
> quantity of storage to be scanned will generally be larger. Smaller mins result
> in shorter, more frequent garbage collections.

**§21.10.3 "DIVERT-AGC"** (verbatim):

> "DIVERT-AGC" ("Automatic Garbage Collection") occurs just before a deferrable
> garbage collection because of exhausted movable garbage-collected storage.
> Enabling this interrupt is the only way to tell from a MDL program that a
> garbage collection is about to occur. A handler takes two arguments: a FIX
> telling the number of words needed and an ATOM telling what initiated the
> garbage collection (above). If it wishes, a handler can avoid a garbage
> collection by calling BLOAT. If the pending request for garbage-collected
> storage cannot then be satisfied, a garbage collection occurs anyway.
> AGC-FLAG is SET to T while the handler is running, so that new storage
> requests do not try to cause a garbage collection.

## gc-min growth policy in this implementation

The MDL manual makes clear that `min` is the floor the **garbage collector**
ensures after a **collection**. It is not a floor the BLOAT handler must
maintain. BLOAT is explicitly the handler's mechanism to *avoid* a collection;
when BLOAT satisfies the pending request, no collection runs and gc-min does not
apply.

**Before round-3 fix (`4e71e3a`):** the gc-min check ran unconditionally after
any pressure event (DIVERT-AGC → BLOAT or GC), collapsing a game-designed
diversion schedule: probe scenario (cap=0, BLOAT words+10 → cap=12 on 850a87f)
inflated to cap=8192 on 4e71e3a, and a game-like BLOAT(words+200) handler with
1010 allocs gave only 1 diversion instead of 10 — matching the reviewer's
observation of 85 diversions (850a87f) vs 2 (4e71e3a) for 300 k cells.

**After round-3 fix (this commit):** a `collected?` flag is set to `#t` only
when `mdl-collect-logical!` actually ran. The gc-min growth block is guarded by
`(when collected? ...)`. BLOAT that satisfies the request leaves `collected?`
as `#f`; gc-min is not applied.

**Explicit `<GC>` (mdl-gc):** calls `mdl-collect-logical!` directly, bypassing
the pressure path entirely. It does not apply gc-min growth, leaving capacity
unchanged. This matches the manual: `min` is a parameter of the automatic
collection process, not of a manually triggered sweep.

## Implementation: final growth formula

When a pressure collection ran and `free-after < max(words, gc-min)`:

```
needed = used + max(words, gc-min)          ; gc-min = 8192 initially
grown  = min(fix-max, max(needed, ceil(capacity × 3/2)))
```

where `fix-max = 2^35 − 1`.  If `needed > fix-max`, a strict Racket error is
raised immediately (not an MDL LVAL error).

The factor 3/2 amortises O(n²) cost from linear increments against a growing
live set to O(n log n) total work.

## Root cause: file and line

`mdl/runtime/core.rkt`, function `mdl-track-allocation!`:

**R2 (original bug, 850a87f):** flat +8192 linear increment:
```racket
(when (> (+ (mdl-memory-used memory) words) (mdl-memory-capacity memory))
  (set-mdl-memory-capacity!
   memory (+ (mdl-memory-used memory) (max words 8192))))
```

**Round-2 regression (4e71e3a):** gc-min check fired unconditionally after any
pressure event, not just after a collection:
```racket
(let* ([gc-min (current-mdl-gc-min)]
       [free-after (mdl-memory-free memory)])
  (when (< free-after (max words gc-min))
    ... grow ...))
```

**Final fix (this commit):**
```racket
(define collected? #f)
(when (> (+ (mdl-memory-used memory) words) (mdl-memory-capacity memory))
  (mdl-collect-logical! 2 initiator)
  (set! collected? #t))
(when collected?
  (let* ([gc-min (current-mdl-gc-min)]
         [free-after (mdl-memory-free memory)])
    (when (< free-after (max words gc-min))
      ... grow ...)))
```

## Remaining risks and unsupported cases

1. **BLOAT > fix-max**: if a DIVERT-AGC handler calls `<BLOAT N>` where
   `N + used > fix-max`, the capacity will exceed the MDL FIX range. This is
   not checked. Left as a follow-up: the game's handlers target ~4000-word
   margins, which are many orders of magnitude below fix-max.

2. **Bookkeeping list length**: the ledger maintains one weak-box entry per
   allocation. With geometric growth, sweeps happen O(log n) times total for a
   growing live set, so amortised cost is O(log n) entries touched per
   allocation. For a 1977 Zork load (1229 forms), this is not a concern.

3. **fix-max overflow error**: raised by `'mdl-gc` with a Racket error message.
   Not an MDL LVAL error. At fix-max = 34,359,738,367 logical words, this is
   unreachable in practice.

4. **BC vs CS liveness**: the REST test uses `make-shared-and-return-tail` to
   control scope; `reclaimed = 2` is stable on BC. The game-like BLOAT test uses
   a mutable `sink` to prevent dead-code elimination of live cells.

## Proposed docs/SEMANTICS.md section

### Logical movable-storage GC (capacity growth policy)

The logical storage ledger tracks MDL LIST cells, VECTORs, and UVECTORs via
host weak boxes.  When an allocation would exceed logical capacity:

1. **DIVERT-AGC** is emitted with `(words initiator)`.  If a handler calls
   `BLOAT`, the extra free words may satisfy the request with no GC. In this
   case gc-min does NOT apply; `BLOAT` is the handler's mechanism for
   postponing a collection.
2. If still short after DIVERT-AGC, a full host-GC sweep (`collect-garbage
   'major`) is run, reclaiming dead entries.  The **GC** event is emitted with
   `(elapsed-seconds reason initiator)`. A `collected?` flag records that a
   sweep ran.
3. If `collected?` is true and `free-after < max(words, gc-min)` (gc-min = 8192
   initially, per MDL manual ch.22 §22.5), capacity is expanded:
   ```
   needed  = used + max(words, gc-min)
   new-cap = min(fix-max, max(needed, ceil(old-cap × 3/2)))
   ```
   If `needed > fix-max = 2^35 − 1`, a strict Racket error is raised.

**Explicit `<GC>`** does not apply gc-min growth: it calls the sweep directly,
leaving capacity unchanged. This matches the manual: `min` is an automatic-GC
parameter set by `<GC min>` or `<BLOAT ... min ...>`.

The ledger is an **approximation** of historical MDL accounting: it tracks
allocation lifetimes through the host GC, not a hand-managed copying collector.
Reported `used` / `free` / `capacity` values reflect this approximation and are
not equivalent to what PDP-10 Muddle would have reported.

The `BLOAT` primitive sets an explicit free-word floor (`capacity = used +
free-words`) and is unaffected by the automatic growth policy. `GC` returns the
number of logical words reclaimed by the sweep (may be less than the number of
host-collected bytes).
