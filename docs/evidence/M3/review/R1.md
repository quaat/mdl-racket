## Finding (restated)

At 850a87f, `mdl-printstring` (`mdl/runtime/core.rkt:3038`) defaulted its
channel to `(mdl-lval "OUTCHAN")`. Only `make-mdl-session`
(`mdl/loader.rkt:70-75`) bound INCHAN/OUTCHAN, so any context without a
loader session failed on `<PRINTSTRING "x">`. In addition, PRINTSTRING
(`core.rkt:3048`, `display`), TERPRI (`:3058`, `newline`) and CRLF (`:3066`,
`newline`) always wrote to Racket's `current-output-port`. The channel was
only checked, never used. A second session's OUTCHAN was rejected only by
accident: its type ATOM came from another atom space, so the error said
"requires an output channel". The channel was in fact a valid output channel.
The runtime has no PRINC, PRIN1 or PRINT SUBRs, so nothing else needed
rerouting.

## Manual contract

Source: https://mdl-language.readthedocs.io/en/latest/11-input-output/, fetched 2026-11-22.

- §11.2.7: "The channel used by default for output SUBRs is the local value
  of the ATOM OUTCHAN." "INCHAN and OUTCHAN also have global values,
  initially the CHANNELs directed at the terminal running MDL." "Initially,
  INCHAN's and OUTCHANs local and global values are the same."
- §11.4.2.2: `PRINTSTRING buffer:string channel count:fix` "returns the
  number of characters output."
- §11.1.2.4 / §11.1.2.5: TERPRI returns `#FALSE ()`; CRLF returns `T`.
- §11.2.1: READ-mode channels permit only input SUBRs.
- The manual does not say which OBLIST the ATOMs are on. Confusion
  (`macros.cpp:3021-3022`) creates both on ROOT.

The brief proposed LVAL-then-GVAL resolution. Neither the manual nor
Confusion supports a GVAL fallback for the omitted argument, so this fix uses
**LVAL only**. Confusion's `mdl_setup_frame_for_print` reads only
`mdl_local_symbol_lookup(OUTCHAN)` and fails with "No channel for PRINT".
GVAL fallback appears only in Confusion's error-REPL recovery
(`macros.cpp:3619-3630`), not in the SUBRs.

## Design

The channels are session-owned (`mdl/runtime/core.rkt`):

- `atom-space` gains four fields: `inchan`, `outchan`, `channels` and
  `terminals`. `make-mdl-atom-space` interns `INCHAN`/`OUTCHAN` in ROOT
  (`:1747`).
- `host-channel (direction port)` (`:2459`). `mdl-make-terminal-channel mode
  [port]` (`:2461`) builds the documented 19-slot VECTOR. It registers the
  VECTOR's storage object in the current atom space's weak table with its
  host port. Port `#f` means "the current Racket port at each operation".
  A port of the wrong direction fails.
- Initial bindings without a session: `terminal-channel-option` (`:2480`) is
  the end-of-frames fallback of `local-option` (`:590`) and the miss
  fallback of `global-option` (`:1605`). It returns one lazily created
  READ/PRINT pair per atom space (`default-terminal-channels`, `:2487`).
  `.OUTCHAN` and `,OUTCHAN` are therefore `==?` and `ASSIGNED?` is T. An
  explicit SET/SETG/binding shadows the fallback, as does a session's own
  binding or `GUNASSIGN`. No process-global channel exists. The default
  atom space was already a module-level default before this change; its
  channels follow whichever port is current.
- `default-output-channel` (`:2498`): the LVAL of `OUTCHAN!-ROOT`. It uses
  the ROOT atom from the atom space, not a lookup by PNAME through the
  current OBLIST path. If the LVAL is unassigned, it fails with "no channel".
- `channel-output-port` (`:2507`) checks, in Confusion's order:
  1. The value must be a CHANNEL, else "attempt to write to non-channel".
  2. Its storage must be registered in **this** atom space, else "CHANNEL
     is not open in this MDL session". This covers cross-session and future
     forged channels.
  3. The host direction must be PRINT **and** the mode slot (NTH 2) must
     still say `"PRINT"`, else "<SUBR> requires an output channel".

  It then returns the channel's port, or `current-output-port` when the
  port is `#f`.
- PRINTSTRING, TERPRI and CRLF (`:3117`, `:3131`, `:3135`) default to
  `default-output-channel` and write with `write-string`/`newline` to that
  port. PRINTSTRING checks the channel first, then the buffer, then the
  count, matching Confusion's order.
- PRINTSTRING still returns the count, which is the existing documented
  choice. The manual returns a count; Confusion returns the STRING. No new
  evidence changes this.
- `make-mdl-session root #:output-port p #:input-port q`
  (`mdl/loader.rkt:64`) passes the ports to its terminal channels. Both
  default to `#f`, so existing callers and tests that wrap a call in
  `parameterize current-output-port` behave as before. The input port is
  stored on the READ channel's host record. This is the hook for S3
  READSTRING/READCHR. No input primitive reads it yet.

## Remaining risks and unsupported cases

- `CHTYPE` between CHANNEL and VECTOR is still rejected ("unsupported built-in
  TYPE conversion"), although Confusion allows it. The host registry is keyed
  by VECTOR storage, so the round trip will keep the channel once CHTYPE
  supports it. A forged `<CHTYPE [...] CHANNEL>` would then fail as "not open
  in this MDL session".
- The binding of OUTCHAN to the channel for the duration of the output
  (§11.2.7, "PRINT binds OUTCHAN") is not modelled. It is unobservable until
  PRINTTYPE-style user hooks exist.
- `UNASSIGN` is not a runtime SUBR, so "LVAL of OUTCHAN unassigned" is only
  reachable through Racket. That path fails with "no channel".
- Output is not flushed after each SUBR. Interactive stdout with READ
  interleaving belongs to S3.
- The line width and other slots, such as `<PUT ,OUTCHAN 13 80>`, are stored
  but not interpreted. MDL CR/LF remains normalized to LF, as already
  documented.
- No input primitive uses the injected input port yet (READSTRING is
  deferred).

## Proposed docs/SEMANTICS.md section

### M3 session-owned CHANNEL ports and default OUTCHAN (review R1)

Manual §11.2.7 makes the default channel for output SUBRs the **local
value** of OUTCHAN. INCHAN and OUTCHAN also have global values, and
initially the local and global values are the same terminal CHANNELs.
Pinned Confusion puts both ATOMs on ROOT. Its PRINT-family SUBRs read only
the LVAL. Rebinding OUTCHAN with SETG does not change the default, and a
PROG binding does (`docs/evidence/M3/review/r1-channel-reference.json`).

Every atom space interns `INCHAN!-ROOT` and `OUTCHAN!-ROOT`. When no frame
binds them, their top-level LVAL and their GVAL are one lazily created
READ/PRINT terminal CHANNEL pair owned by that atom space. This applies to
standalone `#lang mdl` modules, direct runtime use, `mdl-eval` and compiled
evaluation. A loader session binds its own pair explicitly. Each CHANNEL
VECTOR is registered with a host record in its owning atom space. The
record holds the direction and an optional Racket port. With no port, the
channel uses the current Racket port at each operation.
`make-mdl-session #:output-port/#:input-port` injects session ports. The
input port is reserved for later READ primitives.

PRINTSTRING, TERPRI and CRLF take an optional channel, defaulting to
`.OUTCHAN` (ROOT ATOM, LVAL only). They write to that channel's port and to
no other. A non-CHANNEL fails ("attempt to write to non-channel"). So does
a CHANNEL that is not registered in the current session (foreign or
forged), and a channel whose host direction or mode slot is not PRINT.
PRINTSTRING applies count and return-value rules from the M3 PRINTSTRING
section above. It returns the count of characters written, a recorded
deviation from Confusion, which returns the STRING. TERPRI returns
`#FALSE ()` and CRLF returns `T`. Both emit LF only. CHTYPE between CHANNEL
and VECTOR, OUTCHAN rebinding during output, flushing, and the line-width
slots remain unsupported or unmodelled.
