## Finding (restated)

At 850a87f, `mdl-printstring` (`mdl/runtime/core.rkt:3038`) defaulted its
channel to `(mdl-lval "OUTCHAN")`. Only `make-mdl-session`
(`mdl/loader.rkt:70-75`) bound INCHAN/OUTCHAN, so any context without a
loader session failed on `<PRINTSTRING "x">`. In addition, PRINTSTRING
(`core.rkt:3048`, `display`), TERPRI (`:3058`, `newline`) and CRLF (`:3066`,
`newline`) always wrote to Racket's `current-output-port`. The channel was
only checked, never used. A second session's OUTCHAN was rejected only by
accident: its type ATOM came from another atom space, so the error said
"requires an output channel". The channel was in fact a valid output channel.
The runtime has no PRINC, PRIN1 or PRINT SUBRs, so nothing else needed
rerouting.

## Manual contract

Source: https://mdl-language.readthedocs.io/en/latest/11-input-output/, fetched 2026-11-22.

- §11.2.7: "The channel used by default for output SUBRs is the local value
  of the ATOM OUTCHAN." "INCHAN and OUTCHAN also have global values,
  initially the CHANNELs directed at the terminal running MDL." "Initially,
  INCHAN's and OUTCHANs local and global values are the same."
- §11.4.2.2: `PRINTSTRING buffer:string channel count:fix` "returns the
  number of characters output."
- §11.1.2.4 / §11.1.2.5: TERPRI returns `#FALSE ()`; CRLF returns `T`.
- §11.2.1: READ-mode channels permit only input SUBRs.
- The manual does not say which OBLIST the ATOMs are on. Confusion
  (`macros.cpp:3021-3022`) creates both on ROOT.

The brief proposed LVAL-then-GVAL resolution. Neither the manual nor
Confusion supports a GVAL fallback for the omitted argument, so this fix uses
**LVAL only**. Confusion's `mdl_setup_frame_for_print` reads only
`mdl_local_symbol_lookup(OUTCHAN)` and fails with "No channel for PRINT".
GVAL fallback appears only in Confusion's error-REPL recovery
(`macros.cpp:3619-3630`), not in the SUBRs.

## Design (as revised after the independent review)

The first version (`fafa379`) computed the initial INCHAN/OUTCHAN on lookup
through fallbacks in `local-option`/`global-option`. The independent review
showed that this was invisible to GDECL, MANIFEST and the SETG manifest
check, and that standalone modules shared one cached pair (see "Review
follow-up"). The current design binds the channels eagerly into the tables
instead. Line numbers below refer to `mdl/runtime/core.rkt`.

**Execution contexts**
- `mdl-context (globals locals atom-space)` (`:2494`).
- `make-mdl-context #:output-port #:input-port` (`:2496`) is the shared
  context constructor. It creates fresh tables and a fresh atom space, then
  calls `mdl-ensure-terminal-channels!`.
- `call-with-mdl-context` (`:2507`) runs a thunk with that context's three
  parameters set.
- `make-mdl-session` (`mdl/loader.rkt:75`) builds its context with
  `make-mdl-context`.
- The process-wide default context (the parameters' initial values) is
  initialized by `(mdl-ensure-terminal-channels!)` at the end of `core.rkt`
  (`:3633`).
- Every `#lang mdl` module starts with `(mdl-ensure-terminal-channels!)`
  (`mdl/lang/reader.rkt:13`).

**`mdl-ensure-terminal-channels!` (`:2513`)**
- For each of `INCHAN!-ROOT`/`OUTCHAN!-ROOT`, it binds a fresh terminal
  CHANNEL as the top-level LVAL (the last local frame) and as the GVAL (via
  `mdl-setg!`). It does this only when the ATOM has neither a top-level LVAL
  nor a GVAL entry.
- It is idempotent and never replaces a host's or a program's binding.
- The bindings are ordinary table entries, so GDECL, MANIFEST, SETG,
  `ASSIGNED?` and `GASSIGNED?` behave as for any other binding.
- There are no lookup fallbacks any more.

**Isolation boundary**
- Channels belong to a context.
- Different contexts (each session, each `make-mdl-context`) have distinct
  CHANNEL objects and host records.
- `#lang mdl` modules execute in the ambient context, as all their globals
  already did. Modules instantiated in the same context therefore share its
  channels exactly as they share every other global. This includes all
  standalone modules run in the process-wide default context.
- That default context is the pre-existing shared default (globals, locals,
  atom space). This change does not create it, but it does give it one
  INCHAN/OUTCHAN pair. The earlier claim "no process-global channel" was
  wrong for the default context and is withdrawn.
- A context assembled by hand, by setting the parameters to fresh tables
  without the constructor, has no INCHAN/OUTCHAN until the host calls
  `mdl-ensure-terminal-channels!`. In such a context PRINTSTRING with no
  channel fails with "no channel: OUTCHAN has no local value" (strict).

**Host channels (`:2463`, `:2465`)**
- `mdl-make-terminal-channel mode [port]` builds the documented 19-slot
  VECTOR.
- It registers a `host-channel (direction port)` in the current atom space.
  The key is the **backing storage**, the Racket vector shared by all views
  of the mdl-array (`mdl-array-storage`). Every view of that storage that is
  typed CHANNEL reaches the same host record.
- Port `#f` means "the current Racket port at each operation". A port of
  the wrong direction fails.

**`CHTYPE` to CHANNEL (`:3043`)**
- CHANNEL is now an allowed built-in CHTYPE target (primtype VECTOR), as in
  Confusion's `chtype-vector-roundtrip`.
- This is safe because a VECTOR whose storage has no host record in this
  session is rejected with "CHANNEL is not open in this MDL session".
- It makes the storage keying observable from MDL code.

**Default channel and checks (`:2531`, `:2540`)**
- `default-output-channel` returns the LVAL of the ROOT ATOM `OUTCHAN`.
  The GVAL is not consulted.
- `channel-output-port` checks, in Confusion's order:
  1. The value must be a CHANNEL, else "attempt to write to non-channel".
  2. Its storage must be registered in this atom space, else "CHANNEL is
     not open in this MDL session".
  3. The host direction must be PRINT **and** the view's mode slot (NTH 2)
     must be `"PRINT"`, else "<SUBR> requires an output channel".
- PRINTSTRING then checks the buffer and then the count. Confusion
  confirmed this order: `order-*` cases in `r1-followup-reference.json`.
- PRINTSTRING, TERPRI and CRLF write only to that channel's port, or to
  `current-output-port` when the port is `#f`.
- PRINTSTRING still returns the count, which is the documented deviation
  from Confusion.

**Session ports**
- `make-mdl-session root #:output-port p #:input-port q` passes the ports
  through `make-mdl-context`.
- The input port is stored on the READ channel's host record, ready for
  S3 READSTRING/READCHR. Nothing reads it yet.

## Remaining risks and unsupported cases

- Contexts assembled by hand (fresh parameters without `make-mdl-context`)
  have no INCHAN/OUTCHAN. This is deliberate: there is no hidden fallback.
- All standalone modules run in the process-wide default context, so they
  share its globals and channels. A host that needs isolation must run each
  module under its own `make-mdl-context`.
- TOP and BACK are not on this base. With storage keying, their views reach
  the same host record once they are retyped CHANNEL, and they must still
  pass the mode-slot check.
- The binding of OUTCHAN to the channel for the duration of the output
  (§11.2.7, "PRINT binds OUTCHAN") is not modelled. It is unobservable until
  PRINTTYPE-style user hooks exist.
- `UNASSIGN` is not a runtime SUBR, so "LVAL of OUTCHAN unassigned" is only
  reachable through Racket. That path fails with "no channel".
- Output is not flushed after each SUBR. Interactive stdout with READ
  interleaving belongs to S3.
- The line width and other slots, such as `<PUT ,OUTCHAN 13 80>`, are stored
  but not interpreted. MDL CR/LF remains normalized to LF, as already
  documented.
- No input primitive uses the injected input port yet (READSTRING is
  deferred).

## Proposed docs/SEMANTICS.md section

### M3 execution contexts, session-owned CHANNEL ports, default OUTCHAN (review R1)

**Manual and Confusion**
- Manual §11.2.7 makes the default channel for output SUBRs the **local
  value** of OUTCHAN.
- INCHAN and OUTCHAN also have global values. Initially the local and
  global values are the same terminal CHANNELs.
- Pinned Confusion puts both ATOMs on ROOT. Its PRINT-family SUBRs read only
  the LVAL. Rebinding OUTCHAN with SETG does not change the default, and a
  PROG binding does (`docs/evidence/M3/review/r1-channel-reference.json`).

**Execution contexts**
- An execution context is one globals table, one local frame stack and one
  atom space.
- INCHAN and OUTCHAN are the atom space's seeded ROOT atoms from the
  historical inventory (`mdl/runtime/root-names.rktd`, R3/R4). The channel
  machinery holds exactly those atoms (`mdl-root-atom` identity) and never
  resolves them through `.OBLIST`. A user OUTCHAN that shadows ROOT in a
  BLOCK is a different, unbound atom, and it does not redirect the default
  channel.
- Each context starts with both ATOMs bound, as top-level LVAL and as GVAL,
  to one READ/PRINT pair of terminal CHANNELs owned by that context.
- The bindings are stored in the tables when the context is created:
  - by `make-mdl-context`, which `make-mdl-session` also uses;
  - for the process-wide default context, when the runtime loads;
  - by the idempotent `mdl-ensure-terminal-channels!` that begins every
    `#lang mdl` module. It binds only an ATOM that has neither binding.
- GDECL, MANIFEST, SETG, `ASSIGNED?` and `GASSIGNED?` treat them like any
  other binding.
- `#lang mdl` modules run in the ambient context. Modules in the same
  context share its channels, as they share all globals. Separate contexts
  never share channels.
- A context assembled by hand without the constructor has no
  INCHAN/OUTCHAN until `mdl-ensure-terminal-channels!` is called.

**Host channels**
- Each CHANNEL's backing VECTOR storage is registered in its owning atom
  space with a host record: direction plus an optional Racket port. With no
  port, the channel uses the current Racket port at each operation.
- `make-mdl-session #:output-port/#:input-port` and
  `make-mdl-context #:output-port/#:input-port` inject ports. The input port
  is reserved for later READ primitives.
- CHTYPE may retype a VECTOR as CHANNEL, as in Confusion. Only storage that
  is registered in the current session acts as an open channel. REST of a
  CHANNEL is a VECTOR, as in Confusion.

**PRINTSTRING, TERPRI and CRLF**
- They take an optional channel, defaulting to `.OUTCHAN` (ROOT ATOM, LVAL
  only), and write only to that channel's port.
- The channel is checked first, in Confusion's order:
  1. A non-CHANNEL fails ("attempt to write to non-channel").
  2. A CHANNEL not registered in this session fails ("not open").
  3. A host direction or mode slot (NTH 2) other than PRINT fails ("requires
     an output channel").

  PRINTSTRING then checks the STRING buffer and then the count.
- PRINTSTRING returns the count of characters written. This is a recorded
  deviation: Confusion returns the STRING.
- TERPRI returns `#FALSE ()` and CRLF returns `T`. Both emit LF only.

**Recorded deviations and unmodelled behaviour**
- This runtime's GDECL checks an existing value; Confusion does not.
- This runtime's SETG refuses to change an assigned MANIFEST; Confusion
  allows it.
- OUTCHAN rebinding during output, flushing, and the interpretation of the
  line-width slots are not modelled.
