## Findings restated

**R3.** The active atom search path was kept in two places. `mdl-set!`
wrote both a frame binding and a separate atom-space `lookup` field;
`mdl-lval` read the frame chain and fell back to that field; `mdl-atom` read
only the field. PROG/AUX/formal bindings of `OBLIST` created frame bindings
without touching the field, and frame exit never restored it. So `.OBLIST`
and actual atom resolution could disagree, and a SET inside a binding frame
leaked past the frame's exit.

**R4.** Runtime-internal code called `(mdl-atom "T")`, `(mdl-atom "OBLIST")`,
`"DECL"`, `"LOSE"`, `"REDEFINE"`, type names, and so on. These went through the
user-mutable search path, so a user BLOCK could make them resolve to the
wrong atom or intern new atoms in a user OBLIST. The builtin SUBR check in
`global-option` also called `mdl-atom`, which interned atoms as a side
effect of plain GVAL queries.

**Found while fixing R3 (same root cause, fixed here).** Compiled code
evaluated `(mdl-atom "NAME")` every time it ran, so atoms in a function body
were resolved at call time against whatever `.OBLIST` was current then,
not when the code was read. Once bindings of OBLIST are honoured (R3), that
would have made `<PROG ((OBLIST ...)) FOO>` re-intern `FOO`. Atom identity
must be fixed at read time.

## Root cause (at `850a87f`)

- `mdl/runtime/core.rkt:596-603` `mdl-lval`: fell back to `atom-space-lookup` when OBLIST was locally unbound. A bound-but-unassigned OBLIST also fell back, because `local-option` returned the unassigned token.
- `core.rkt:605-617` `mdl-set!`: `set-atom-space-lookup!` plus a frame write (two copies).
- `core.rkt:619-627`, `638-687`, `717-731` and the interpreted binder (~1288): new frames never updated the cached lookup, and the cache was not restored on exit.
- `core.rkt:2118-2135` `mdl-atom`: resolved through `atom-space-lookup` only.
- `core.rkt:1605-1610` `global-option`: `(eq? atom (mdl-atom (mdl-atom-pname atom)))`. This interned uninterned or foreign atoms, and treated any same-named atom on the current path as the builtin.
- 73 internal `(mdl-atom "...")` call sites in `core.rkt`, plus `loader.rkt:72,81-82` and `compiler.rkt` (AND/RETURN/NOT `T`, reader-macro LVAL/GVAL/QUOTE heads).
- `core.rkt:1741-1765`: built-in TYPE atoms were placed in INITIAL, not ROOT, and no SUBR name or `T` was pre-seeded. So "internal" atoms were interned lazily, into whatever OBLIST came first at that moment.
- `mdl/compiler.rkt` (every `` `(mdl-atom ,name) `` emission): atoms were resolved at run time of the compiled code, not at read time.

## Manual contract

Fetched from https://mdl-language.readthedocs.io/en/latest/15-lexical-blocking/ on 2026-11-22:

- 15.3: "READ looks up the PNAME of the ATOM in a LIST of OBLISTs, the LVAL of the ATOM OBLIST by default."
- 15.5: "<1 .OBLIST> initially contains no ATOMs"; "<2 .OBLIST> contains all the ATOMs whose GVAL are SUBRs or FSUBRs, as well as OBLIST, DEFAULT, T, etc."; "the SUBR ROOT ... always returns that OBLIST."
- 15.6: BLOCK "returns its argument after 'pushing' the current LVAL of the ATOM OBLIST and making its argument the current LVAL"; ENDBLOCK pops it; "this 'pushing' and 'popping' of .OBLIST is entirely independent of functional application, binding, etc."
- The manual says nothing explicit about the identity of already-read atoms. It follows from READ producing ATOM objects (15.3), and pinned Confusion confirms it (`lexical-identity-function-body`).
- The manual page does not define the empty trailer `A!-`. Confusion shows that it names ROOT (see below).

## Design

1. **One authoritative path (R3).** The active search path is the ordinary
   LVAL of the session's ROOT `OBLIST` atom: the innermost frame binding,
   including the session top-level frame. Only when no frame binds it does
   the session's startup list `(INITIAL ROOT)` apply. That default is never
   written after the session is created. There is no cached copy.
   `local-option` supplies the default, so `.OBLIST`, `ASSIGNED?`, `VALUE`,
   `current-lookup-path` (used by `mdl-atom` and BLOCK) and SET all see the
   same value. Restoration on every exit path comes from the existing
   `parameterize` of `current-mdl-locals`. A binding that exists but is
   unassigned is unassigned.
2. **BLOCK/ENDBLOCK** keep the session stack. BLOCK pushes the current path
   and SETs; ENDBLOCK pops and SETs. Both are independent of frames, as in
   manual 15.6 and Confusion.
3. **Read-time identity.** `compile-expression` collects each user-text atom
   reference of a top-level expression (`atom-ref`) and binds them all in an
   outer `let`, in first-occurrence order, before the body and the retained
   literals. The loader evaluates each form right after reading it, so this
   is read-time interning through the same authoritative path. FLOAD and
   `%` read-eval inside a binding of OBLIST read under that binding.
4. **ROOT interner (R4).** Each atom space seeds ROOT with the built-in TYPE
   atoms (moved from INITIAL), every `builtin-table` SUBR name, and a short
   list of internal names, each confirmed in Confusion's startup ROOT
   (`internal-name-placement`): T, QUOTE, REDEFINE (values the runtime
   produces or compares), MUDDLE, INCHAN, OUTCHAN, FLOAD (interpreter
   globals and channels), INTERRUPTS (the interrupt OBLIST's name), and
   DEFINE, DEFMAC, FUNCTION, PROG, REPEAT, RETURN, AGAIN, UNWIND, GDECL,
   COND, AND, OR, NOT (FSUBRs the compiler handles by name). GO and
   DIVERT-AGC were seeded at `704709c` and removed in the review follow-up:
   Confusion has them in neither ROOT nor INITIAL, and the runtime never
   uses them as atoms.
   `mdl-root-atom` returns these from a per-session cache. It never reads
   `.OBLIST`, never interns, and errors on an unseeded name (strict). Later
   REMOVE/INSERT on ROOT cannot change which atom the runtime means.
   `global-option` treats an atom as a builtin only if it is the cached ROOT
   atom of that name. The default `current-mdl-atom-space` is created after
   `builtin-table`. The reader-macro heads LVAL/GVAL/QUOTE are ROOT atoms.
5. **Empty trailer.** `A!-` names the session ROOT directly. This is required
   because `81tell-repl.mud:116` `TOPLEVEL!-` is now resolved at definition
   time. Before, it sat in an uncalled function body. Without this change,
   R3 regressed the load to 173 forms (see below).
6. **APPLICABLE.** A DECL failure leaf now returns the pattern's own atom
   instead of an internal APPLICABLE atom, so APPLICABLE stays a non-ROOT
   name, as in Confusion.

Inventory: all 73 literal `mdl-atom "..."` sites in `core.rkt` outside
`module+ test` were converted, plus `mdl-atom initiator`, the type-name and
primtype conversions, 3 loader sites and 3 compiler `T` sites. They were not
converted where the name comes from user text: the ATOM SUBR (still makes an
uninterned atom), `binding-atom` on strings (the host API), `!-` trailer
names, `mdl-session-atom`, and the compiler's compile-time substitution
check (`atom-name`). Identity checks now compare against ROOT atoms:
`(eq? … OBLIST)` in local-option/mdl-set!, QUOTE-form detection, FORM type,
PRIMTYPE heads, REST brackets, DECL association, CHANNEL/LOSE/FIX/CHARACTER
type tests, and `mdl-boolean` T. User-read names reach the same atoms
because those atoms exist in ROOT before any text is read.

Review follow-up (MAJOR): PRINTSTRING's default channel was
`(mdl-lval "OUTCHAN")`. That host STRING went through `binding-atom` and
`.OBLIST`, so a user `OUTCHAN!-OB1` on the search path shadowed it
("unassigned MDL local OUTCHAN"), and an unassigned OBLIST binding broke
it ("unassigned MDL local OBLIST"). It now uses
`(mdl-lval (mdl-root-atom "OUTCHAN"))`. `binding-atom` itself is unchanged.
The same entry points (SET, SETG, LVAL, GVAL, …) serve MDL code, which may
pass a STRING (the pre-existing `<SET "FOO" 3>` acceptance), and the host
test/introspection API, which names user atoms such as `"FLAG-NAMES"`.
Both mean "the atom the reader would produce", so routing STRINGs through
`mdl-root-atom` would change MDL behaviour and reject unseeded user names.
The contract is now a comment at `binding-atom`: runtime-internal callers
never pass a STRING. A source audit of `core.rkt` (outside `module+
test`), `loader.rkt` and `compiler.rkt` for STRING literals passed to
lval/set!/gval/setg!/apply/value/gassigned?/assigned?/manifest/gunassign!/
define!/apply-form/with-bindings/binding-atom found no other site.
Branch R1 also rewrites PRINTSTRING's default channel; this change is the
minimal ROOT-atom fix, left for reconciliation at integration.

## Remaining risks and unsupported cases

- **ROOT contents differ from Confusion's.** ROOT is seeded only with this runtime's implemented SUBR names plus the internal list above. The `none known` claim at `704709c` was wrong: GO and DIVERT-AGC were seeded although Confusion has them in neither ROOT nor INITIAL (now removed), and INTERRUPTS, which is in Confusion's ROOT, was missing (now added). Every remaining seeded internal name is confirmed by `internal-name-placement`. Builtin-table names have not each been probed. In the other direction, the review counted 44 Confusion ROOT names (PRINC, PARSE, MEMBER, …) that are absent here, so user text interns them in INITIAL and `OBLIST?` differs. Identity is still consistent within a session. **Follow-up (recommended, not done here):** seed ROOT from a fixed historical name list taken from Confusion's startup ROOT, independent of which SUBRs are implemented. Unimplemented names would stay unbound, failing strictly.
- **Follow-up: backslash-escaped trailers keep the backslash in the PNAME.** `DEAD\!!-WORDS`, `IN\!!-WORDS` and `OUT\!!-WORDS` (`77act1.mud:379-384`, `78melee.mud:301-491`) give PNAMEs with a backslash (`DEAD\!`); Confusion gives `DEAD!`. Checked: `parse-mdl` keeps the raw token `"DEAD\\!!-WORDS"`, and `mdl-atom` splits it at the first `!-`. This predates R3/R4, but these atoms are now interned on WORDS at read time, where before it happened only when the enclosing function ran. They still match nothing in the game vocabulary. Separate issue.
- **Compiler special forms dispatch by name (documented deviation).** The compiler recognises special forms (DEFINE, PROG, COND, SETG, …) and the interpreted evaluator's FSUBR dispatch by PNAME string, not by ROOT atom identity. Under a BLOCK that omits ROOT, `<DEFINE …>` still compiles as DEFINE, which Confusion would treat as an unbound `DEFINE!-NR`. This deviation predates this change.
- **`%` read-eval runs mid-form (documented deviation).** `%` read-eval executes during reading, before the enclosing form's atoms are hoisted. A `%<BLOCK …>` inside a form would therefore change the path for that form's own atoms. In real MDL, atoms read before the `%` would already be interned. Not used by the source.
- **SET of OBLIST is stricter than Confusion.** It requires a valid search list immediately; Confusion defers the failure to the next read. PROG/formal initial values are checked only when an atom is resolved (strict error), and `.OBLIST` itself returns the value as bound.
- **Not implemented:** OBLIST GVAL semantics (Confusion has a GVAL distinct from the LVAL, and nothing here reads it), DEFAULT insertion redirection, READ's explicit look-up argument, `PARSE`/`READ` SUBRs, and print-time trailer selection.
- **Compile-time substitution check interns.** The compiler's compile-time check for substituted ATOM names (`atom-name`) still calls `mdl-atom` and may intern a stray atom before raising its unsupported error.

## Proposed docs/SEMANTICS.md section

### M3 review R3/R4: authoritative OBLIST path, ROOT identity, read-time atoms

The manual (15.3) says READ resolves PNAMEs through the LVAL of OBLIST. That
LVAL is the only search path in this runtime: the innermost binding of the
session's ROOT `OBLIST` atom, including the session top-level frame.
Without any binding, the session's startup list `(INITIAL ROOT)` applies.
There is no separate cached copy. PROG/AUX/formal bindings, SET, BLOCK and
ENDBLOCK all act on the ordinary LVAL, so normal exit, RETURN/AGAIN, ERROR
unwinding and host exceptions all restore resolution together with the
binding. A bound-but-unassigned OBLIST is unassigned. BLOCK pushes the
current path and SETs; ENDBLOCK pops and SETs. Both are independent of
function frames (15.6): a BLOCK inside a frame that binds OBLIST changes
only that binding, and a later ENDBLOCK sets whichever binding is current
then. SET of OBLIST requires a nonempty LIST of OBLISTs (stricter than
Confusion). Atom resolution fails explicitly when the current LVAL is
unassigned or not such a LIST.

Atoms are identified when their top-level expression is read. Compiled code
resolves every user-text ATOM of an expression once, before the expression
runs, so function bodies keep their read-time atoms when OBLIST is rebound
later. FLOAD inside a binding of OBLIST reads the file under that binding.
Reader-macro heads (LVAL, GVAL, QUOTE) are ROOT atoms. `A!-` (empty
trailer) names ROOT directly and inserts into ROOT on a miss. `A!-B` looks
up B through the current path.

Following 15.5 and pinned Confusion, ROOT holds T, OBLIST, the built-in TYPE
names and every built-in SUBR/FSUBR name; INITIAL starts empty. Each session
seeds its ROOT at creation and caches those atoms. Runtime-internal names
(truth value T, type names, DECL/OBLIST indicators, REDEFINE, QUOTE, GC
initiators, interpreter globals) are always these cached ROOT atoms. They
are never looked up through `.OBLIST`, never interned into a user OBLIST,
and are not affected by later REMOVE/INSERT on ROOT. A built-in SUBR is the
GVAL of its ROOT atom only: a same-named atom on another OBLIST, or an
uninterned one, is unbound, and GVAL queries never intern. Evidence:
`evidence/M3/review/R3R4-oblist-reference.json`,
`R3R4-oblist-error-reference.json`; tests `tests/oblist_identity_test.rkt`.
Runtime-internal code never passes a host STRING to `binding-atom`; STRINGs
there come from MDL code or the host API and resolve through `.OBLIST`.
Deviations: ROOT contains this runtime's builtin set, not Confusion's full
set. Compiler special forms are still recognised by PNAME. OBLIST's GVAL,
DEFAULT, READ look-up arguments and print-time trailers are not implemented.
