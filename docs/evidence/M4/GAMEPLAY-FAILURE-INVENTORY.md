# M4 gameplay failure inventory (Phase 1 of epic #163)

Date: 2026-11-24. Branch `feat/m4-failure-inventory` on `main` 065098d.
Gate label: **discovery evidence. Not a PLAYABLE, SCENARIO_PARITY or M4 claim.**

This file lists where the unchanged December 1977 game can still fail under
this runtime. It separates **normal game responses**, which the original
gives too, from **runtime failures**. An unknown-word message is a normal
response. An unassigned operator, or a strict error that reaches the
launcher and ends the session, is a runtime failure. No runtime code was
changed in this slice. Fixes are separate slices (see the fix order at the
end). Issue and PR columns read "to create".

## Method

1. **Static sweep** (`scripts/sweep_operator_heads.py`). It reads the
   twelve loaded files plus `77loadall.mud` and `run.mud` with a standalone
   MDL reader. Its count of top-level objects is 13 + 1216 = **1229**, the
   same number of forms our loader completes.

   It lists every operator use:
   - a FORM head;
   - a head generated by `<FORM X …>` in a DEFMAC body;
   - a GVAL applied by APPLY, MAPF or MAPR.

   It classifies each name as one of:
   - runtime builtin: builtin-table keys, root-internal names, compiler
     special forms, FLOAD;
   - game-defined: DEFINE, DEFMAC, SETG, PSETG, MSETG, NEWSTRUC field
     offsets such as `ODESC2`, `OROOM` and `HOBJ` (including after
     `"REST"`), FLAGWORD bits, MAKE-SLOT;
   - local;
   - missing.

   Sites are tagged by context:
   - `comment`;
   - `decl` (#DECL, GDECL, NEWSTRUC and NEWTYPE specifications);
   - `quoted`;
   - `readeval` (`%<…>`);
   - `superseded` (bodies replaced by a later DEFINE: 77patch.mud redefines
     DO-SAVE and DO-RESTORE).

   The sweep also reports two other things:
   - strings turned into code (PARSE/EVAL);
   - non-head ATOMs that name a Confusion ROOT SUBR this runtime lacks.

   Result: 380 operator names. 117 are builtin, 234 game-defined, 24
   missing at a live site, and 5 missing only at comment, decl or
   superseded sites.

   Line numbers here are **physical lines** (`grep -n`). Some numbers in the
   epic's first rough pass differ: ABS is at 77act1.mud:949/951 (not 872)
   and CLOSE at 77rooms.mud:351 and later (not 323). 77act2.mud:53 is
   FWEEP's DEFINE line; its SLEEP call is at :58.
2. **Applied-by-name check** (native diagnostic X1). It walks, in loaded
   pinned Confusion:
   - every RACTION, CXACTION, OACTION, AACTION and HACTION;
   - every VERB's VFCN on the WORDS and ACTIONS OBLISTs.

   There are 767 references and 185 distinct ATOMs. 184 have a FUNCTION
   GVAL, all DEFINEd by the game. **One, `TIME`, is the Confusion ROOT
   SUBR**: the game uses it as a do-nothing verb and room function. Every
   non-ATOM slot is FALSE, so DISPATCH's NOFFSET branch is never reached
   from data.

   `MUDDLE` is 101 natively. This runtime also uses 101. With 101 every
   `<L? ,MUDDLE 100>` ITS branch is skipped.
3. **Native vs ours runs** F1–F13. Each uses the shortest command sequence
   found from the source. Our first differing character is computed against
   the native game text from "Welcome to Dungeon.". F11 is a 125-command
   discovery battery over most of the vocabulary. In this runtime it is
   re-run without any command that fails strictly (`fault_skip`); none
   failed.
4. **Reachability review** of every candidate's enclosing function and
   callers in the source. Classes:
   - (a) reachable by ordinary play;
   - (b) reachable only on an error, debug, interrupt or file path;
   - (c) only in dead, guarded, superseded or compile-time code;
   - (d) unknown.

**INV-01: ABS.** *Status: fixed by M4 S8 (#167). ABS is a builtin, and the operator sweep JSON was regenerated, so ABS is now class `builtin`.*

- *First failing location and call path:* 77act1.mud:951 `<G? <ABS .COUNT> 5>` in CYCLOPS (77act1.mud:934). The call path: RDCOM's demon loop (77rooms.mud:643–647) → FIGHTING (78melee.mud:282), which sets PRSVEC 1 to FIRST?!-WORDS (:308) and calls `<APPLY-RANDOM CYCLOPS>` (:309). ABS also appears at :949 (wake), :1031 (CYCLOPS-ROOM LOOK) and :1050 (AOS-SOS); natively all are reached in F1.
- *Native:* The room text, then "Your sword has begun to glow very brightly." Play goes on.
- *Ours:* The room text, then strict failure `mdl-eval: unassigned or non-applicable MDL operator ABS`. Simply entering the Cyclops Room kills the session. The room is the only route to the treasure room and the Strange Passage.
- *Proposed fix:* implement the ROOT SUBR ABS for FIX and FLOAT, strict on other types and arities. Document it in SEMANTICS and probe Confusion first.
- *Regression test:* a unit test, plus a scenario test over F1's 26 commands compared with the committed native capture.

**INV-02: IMAGE.**

- *First failing location and call path:* 77act2.mud:57 `<IMAGE 7>` in FWEEP (:53). The call path: ROOM-INFO applies the room action on WALK-IN (77rooms.mud:554–555) → BATS-ROOM (77act2.mud:26) → FLY-ME (:39, called at :30) → `<FWEEP 4 1>` (:43). It is also reached by BOOM-ROOM `<FWEEP 7>` (:22): a lit candle or torch in the gas room. That path was not run.
- *Native:* Three `\x07` bytes, then the bat text and a random coal-mine room.
- *Ours:* The Bat Room text, then strict failure `… operator IMAGE`. Entering the Bat Room without garlic (the usual first visit) kills the session.
- *Proposed fix:* implement IMAGE: write the character code raw to the output channel and return the FIX. The transcript must keep the BEL bytes. Decide whether a future web client renders or strips BEL.
- *Regression test:* a unit test, plus a scenario test over F10 compared byte for byte with the native raw stdout.

**INV-03: SLEEP.**

- *First failing location and call path:* 77act2.mud:58 `<SLEEP .SLP>` in FWEEP, on the same call path as INV-02. SLEEP in RECORD (77rooms.mud:740, :746) is unreachable under ADR-0055: the status is never `*600130*`.
- *Native:* `<SLEEP 1>` three times; the run takes 3.25 s against about 0.2 s for the other cases. No text.
- *Ours:* Not yet reached; it is the next form after IMAGE in the same loop.
- *Proposed fix:* implement SLEEP after a maintainer decision. Either it waits for real time (bounded, real clock only) or it returns T without waiting under the fixed and replay clocks. The fixed-clock shim already freezes DSKDATE natively, so `time` output must not change. A server must never block a worker indefinitely.
- *Regression test:* the F10 scenario must end in parity with no strict failure, plus a SLEEP unit test (return value, no clock change under the fixed clock).

**INV-04: TIME.**

- *First failing location and call path:* RDCOM applies the verb function: `<APPLY-RANDOM <VFCN .CV>>` (77rooms.mud:631–632) → `<APPLY <GVAL TIME>>`. Internal verbs WALK-IN, C-INT, DEAD!, FIRST?, IN!, OUT! and HACK? (77dung.mud:2902–2916) and the TURN-TO syntax (:2819) are bound to `TIME`. Of these, only `C-INT` and the TURN-TO syntax can be typed; the others contain a break character or exceed five letters. The room BLROO, the Strange Passage, has the room action `TIME` (77dung.mud:1385). ROOM-INFO applies it on entry (77rooms.mud:555), and RDCOM after every successful command there (77rooms.mud:634).
- *Native:* `c-int` → "Nothing happens." (TIME returns a positive FLOAT). BLROO: the room text, and play goes on.
- *Ours:* `c-int` → strict failure `mdl-gval: unassigned MDL global TIME`. BLROO will fail the same way on entry once INV-01 is fixed. That is source-derived and not yet observed.
- *Proposed fix:* implement the ROOT SUBR TIME. The game only tests whether its value is true, but native TIME reads CPU time, so it is not deterministic. Maintainer decision: derive a deterministic FLOAT from the session (for example, seconds since the session clock started, or a constant positive FLOAT), or record TIME as a clock observation under ADR-0061.
- *Regression test:* the F9 scenario; F8 once INV-01 is fixed; a unit test that TIME has type FLOAT and is true.

**INV-05: help / info.**

- *First failing location and call path:* 77rooms.mud:961 `<OPEN "READ" .FILE1 .FILE2 .DEV .SNM>` in FILE-TO-TTY (:960), called by HELP (:956) and INFO (:954). Behind it are FILE-LENGTH (:970), READSTRING from a file channel (:978, :979) and CLOSE (:983, :984).
- *Native:* Prints the shipped files `MDL/MADADV.HELP` (4274 bytes) and `MDL/MADADV.INFO` (1527 bytes).
- *Ours:* Strict failure `OPEN: mode "READ" is not supported …`.
- *Proposed fix:* the maintainer decides the file I/O policy. Option (1), faithful: a read-only virtual file allowlist of exactly those two shipped files, with OPEN "READ", FILE-LENGTH, file READSTRING and CLOSE on them only. Option (2), stopgap: deny "READ" with the ADR-0055 FALSE, so the game prints "File not found." That is a visible deviation. Either way, no general filesystem access.
- *Regression test:* F6 and F7 compared with native under option (1), or a recorded deviation under option (2). Security-guard tests must show no other file can be opened.

**INV-06: restore.**

**INV-07: PRINT in HANDLE.**

- *First failing location and call path:* 77rooms.mud:251 `<MAPF <> <FUNCTION (X) <PRINT .X>> .ZORK>` in HANDLE (:215). HANDLE is the ERROR handler installed at load (77rooms.mud:258–270). - *Regression test:* a synthetic `<ERROR …>` during play through the real HANDLE, comparing transcript and `quit-after-mdl-error` with native.

The sweep found no strings turned into code on live paths: PARSE and EVAL
appear only at the sites above. The `%` read-time forms contain only `+`,
`ASCII`, `STRING` and `FIND-OBJ` heads (plus `%<>` and `%,X`). They all run
during the load, which completes.

4. **INV-04 TIME** (P0 via the Strange Passage; P2 via `c-int`).

## Limitations and uncertainties

- **Not exhaustive.** The static sweep finds only *missing* operators and
  ATOMs applied by name. It cannot find wrong semantics in implemented
  primitives. Dynamic coverage is the commands above and earlier M4
  scenarios. Not exercised:
  - the dam, the boat and the river;
  - the balloon;
  - the coal-mine machine and basket;
  - the thief's fight and his treasure room;
  - the gas-room explosion (BOOM-ROOM → FWEEP 7);
  - lamp burn-out;
  - CEVENT clock interrupts beyond the troll and cure clocks;
  - turning a TURNBIT object "to" something (the TURN-TO → TIME syntax).
- INV-03 (SLEEP) and INV-04 on BLROO are **source-derived for our
  runtime**: an earlier failure (IMAGE, ABS) masks them in the same run.
  Both were observed natively.
- The round-room route in F10 depends on the RANDOM sequence under this
  clock and this exact command prefix. Any change to an earlier command
  moves the landings.
- The reachability classes (b) and (c) are source judgements. No player
  command was found for them, but none is proven impossible except through
  the recorded decisions (interrupt sources, the OPEN policy).
- Severity P0 is used for session-ending failures at ordinary locations, per
  the epic's definition ("prevents normal gameplay"). Under a narrower
  reading INV-02 to INV-04 could be P1, but the fix order would not change.
